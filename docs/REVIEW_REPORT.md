# pdfenv Skill 技术审查与升级报告

- 审查对象：用户上传的 `pdfenv.zip`（`SKILL.md` / `README.md` / `scripts/read_pdf.py`）。
- 交付版本：`pdfenv v2.2`（为原始版本升级产生的独立 ZIP）。
- 核心目标：**水印不污染阅读内容、正文不被误删、PDF 页面按需渲染、检测与输出可审计可复核**。
- 验证边界：实验使用自建的合成 PDF 页面、重复叠加文字水印、单字竖排水印、扫描页和双引擎渲染；**未取得你最初报告中那篇 210 页博士论文的 PDF 原件**，不能声称在该论文上实测完成。

## 一、对原 Skill 的评价

原版的“直接读取失败→Python 解析→抽样验证→水印清洗”可以作为最低限度的容错路径，但其机制仍不适用于要求准确引用数值、公式和图表的科研审稿。

| 事项 | v1.0 现状 | 问题性质 | v2.2 实施 |
|---|---|---|---|
| 扫描判定 | `Producer` 判断文本型或扫描型 | 元数据不具有识别效力 | 按页文字量、页面图像覆盖度联合抽样 |
| OCR 落地 | 仅描述 pytesseract，但无 OCR 代码 | 功能缺失 | OCR auto/force，Tesseract 检测和超时 |
| 水印去除 | 删除长度 ≤2 的整行 | 可能误删 `a`、`5%`、`R²`、独立编号 | 不按行长删字；对象级/字符级筛选 |
| 水印判据 | 从出现次数高的字符猜测字符集 | 会把正文常用汉字误认为噪声 | 跨页空间复现 + alpha/颜色/旋转/字号 |
| 被水印混入正文 | `extract_text()` 后再过滤 | 文字顺序已被污染 | 拼接前在 glyph 层隔离候选水印 |
| 防误删 | 无删除比例上限和回退 | 无法判定清洗风险 | 按页删除比例上限 + 原文回退 + JSON 审计 |
| PDF 渲染 | 无代码 | 无法核验公式、图表及真实版式 | MuPDF/PDFium、DPI、裁切、切片、图像清单 |
| 渲染核验 | 无 | 缺字可能来自渲染引擎而非 PDF | `parity` 生成两引擎图与差异图 |
| 长论文性能 | pdfplumber 按页解码，无渲染预算 | 大文档耗时及资源风险 | PyMuPDF 快速文本通道；渲染页数/像素上限 |
| 结果格式 | 仅 TXT | 复核和 AI 索引不方便 | TXT/MD/JSON + 审计 JSON + page manifest |

## 二、水印算法升级细节

### 2.1 应在文本重组前处理水印，而非 `extract_text()` 之后

原脚本的关键缺点是：当竖排水印被 PDF 阅读顺序算法拆成字符插入正文行时，后处理清洗已无法准确判断哪些字符属于水印。新脚本先以 PyMuPDF 的 `get_texttrace()` 读取绘制轨迹，获取文字字符、边界框、方向、字号、RGB 与不透明度，再通过 `get_text('rawdict')` 对对应字符进行匹配和保守排除。这一处理保留正文短行和数字，不依靠“哪个字看着像水印”。

### 2.2 多个独立证据而非单一阈值

主要证据包括：**跨页位置重复、低透明度、浅灰色、文字方向（竖排/旋转）、大字号、沿纵向排列的一字一 glyph**。保守模式要求跨页重复与视觉线索相互支持，避免把论文内的小型坐标轴、公式字母、表格数据误删。

但跨页固定位置的灰色章标题、封面淡色题签也可能出现类似特征，算法不具有零误判保证。

### 2.3 自动回退保护

- 预测删除比例 = 候选水印字符数量 / 当前页可见文字轨迹字符数量。
- 默认阈值 35%；超过即停止本页清理，输出原生文本，并在 `.watermark-audit.json` 中标记 `rollback_excessive_removal`。
- 严格论文审稿可以通过 `--max-remove-ratio 0.1` 降到 10%。该阈值是技术上的风险控制，不是“35% 以下肯定正确”的保证。
- 文档本身不修改；审计记录输入 SHA256、样本页、各页删除量和候选字的坐标证据。

## 三、渲染策略优化

### 3.1 先判断是否需要渲染

**应避免将数百页论文统一转成 300 DPI 图片。** 对原生文字层完好的章节使用字符提取；只有排版异常、公式表格、EDS 图、微观形貌图、水印覆盖、模型图和最终数值校对页才渲染。

| 场景 | 指令策略 | 资源考虑 |
|---|---|---|
| 快速了解文档 | `info` / `sample` | 无需转全页图 |
| 正文文本 | `full --clean --format md` | 按页保留 Markdown 标记 |
| 版式验证 | `render --pages 10-12 --dpi 200` | 只渲染目标页 |
| 精读局部公式 | `render --pages 30 --dpi 400 --clip-rel ...` | 高 DPI、低像素总量 |
| 精读整页复杂图 | `render --pages 30 --dpi 450 --tile 2` | 切片降低单张峰值内存 |
| 渲染异常 | `parity --pages 30` | MuPDF vs PDFium 对照 |
| 真扫描页 | `full --pages 30 --ocr auto` | 仅对符合条件页面启动 OCR |

### 3.2 像素预算不等于 DPI

单张图像理论像素数约为：

\[
N_{px}=W_{pt}H_{pt}\left(\frac{DPI}{72}\right)^2
\]

A4 页面近似为 595 × 842 pt，300 DPI 已接近 870 万像素；600 DPI 可超过 3,400 万像素。RGB 8-bit 仅原始像素缓存就可能超过 100 MB，还没计入渲染引擎缓冲、对象和图像压缩内存。应该优先区域高清裁切、其次分块，最后才考虑整体降 DPI。

本版对单张图默认设置 2,600 万像素预算；超过时明确提示提高 tile 或降低 DPI，不静默降低分辨率。默认渲染代表页，有单次页数上限，避免未指定 `--pages` 时转整本。

### 3.3 不要把渲染图改成所谓“无水印真相”

本版 `render` 默认输出**原 PDF 页面原貌**。`--mark-watermarks` 只在派生图上给识别的候选文字框加红线辅助定位，不能说明其他水印已排除。

如果水印被扫描进位图，直接阈值擦除可能同时抹掉细线、图标和公式上下标。即使是矢量文字水印，也可能与正文覆盖。技术上要区分：

- **文本层水印隔离：** v2.2 已实现，可减少输出 MD 的干扰。
- **视觉图像去水印：** 对 PDF 注释对象，可使用 `render --hide-annots` 仅在 MuPDF 派生渲染中隐藏注释（已在合成注释 PDF 中验证）；对嵌入内容流的矢量字样或图片水印仍需要对象分层或像素修复，尚未可靠实现，不能把修复图作为科研原始证据。

## 四、功能测试与性能验证

### 4.1 自动测试

- 10 项 pytest 测试通过：重复透明旋转水印；逐字竖排浅色水印；合法短行/数字保护；1 页文档保守留痕；高删除比例回退；裁切与分块；渲染页数预算；元数据及页范围错误；双引擎差异图；扫描图像自动 OCR。
- 扫描合成页面 OCR 得到 `SCANNED PDF DOCUMENT - STRENGTH 42 MPa`。
- 双引擎 100 DPI 测试样页的像素平均绝对差约为 0.272（RGB 0–255）；属于该样页的观测，不等于所有 PDF 的渲染精度。

### 4.2 性能对比

环境：同一运行容器、同一个 120 页合成 PDF（每页 24 行英文正文和一条透明竖排文字水印）；命令行执行并输出文本，两次运行取较快耗时。

| 脚本 | 耗时 | 备注 |
|---|---:|---|
| 原版 `read_pdf.py full --clean` | 8.69 s | pdfplumber 原有行级过滤 |
| v2.2 `read_pdf.py full --clean` | 4.39 s | PyMuPDF 轨迹筛查和逐字过滤 |

本次样本上新版本耗时约降低 49.5%。测试具有输入与机器依赖性，不能推断在所有真实论文、扫描 PDF、极大量图片或高透明度页面上都能达到这一比率。

## 五、优先级更高的下一轮升级

以下功能需要专门开发，**没有冒称已经实现**：

1. **对象级水印图层分离（P0）：** PDF XObject / ExtGState、soft mask、OCG 与 `seqno` 关联；找出复用水印层，再仅在派生视觉预览中屏蔽该层，并与原渲染并排供确认。
2. **真正的区域版面分析（P0）：** 双栏、数学公式、表格的阅读顺序重建；图注、边注、页眉、文中浮动图框的语义定位。
3. **栅格水印 OCR 防干扰（P1）：** 结合灰度/颜色差异、局部梯度及分区 OCR；图像增强与原图同时保留，严禁凭空还原被完全遮挡的信息。
4. **审稿型数据核验（P1）：** 文中公式数字、表格数据、图上标注与可视化区域对应，给出逐项对照清单和页码坐标。
5. **大批量任务性能（P2）：** 文档指纹缓存、按页增量解析、受控多进程渲染与断点续跑；针对 500–3000 页材料档案才更有意义。

## 六、使用建议

建议 Workbuddy 的日常 SOP：`info -> sample -> full --clean --format md -> read audit -> render 指定问题页 -> 必要时 parity/OCR`。学术场景用清洗后的 MD 建索引、检索论述，用渲染图核查公式、表格、EDS/SEM 标注和图的正确性。

**准确性优先级：PDF 原件 > 原件渲染 > 经过水印过滤的文本 > OCR 推断。**
