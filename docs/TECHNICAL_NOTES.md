# PDF 读取与水印技术设计要点（pdfenv v2.2）

## 1. 威胁模型

可能干扰解析的对象分为五种：

1. **透明文字叠加：** 填充透明度低、字号偏大、跨页面重复且可旋转；可通过 `get_texttrace()` 获取 glyph bbox / opacity / direction，并在文字拼接之前去除。
2. **逐字竖排水印：** 每个字单独水平绘制，组合成竖列；需要按 x 坐标分桶、相似字号、浅色/透明度和纵向跨度识别。
3. **图片/XObject 水印：** 透明 PNG、soft mask 或重复资源对象，不一定存在可过滤的文字层；本版不承诺自动消除。
4. **扫描件中的印记：** 与背景/正文已混成同一栅格，移除可能损坏细字和图线；常规阈值、图像修复不能保证恢复被覆盖的信息。
5. **注释/签章/图层：** 显示取决于渲染器和注释选项；不应未经验证便将其删除。

## 2. 水印决策与回退

- 对全文先抽取少量代表页的 `get_texttrace()`，以归一化几何位置、方向与字体尺寸统计**跨页相同位置**的重复性。
- 对每页单独评估透明度（alpha）、浅色（RGB）、旋转、字号、跨页重复、纵向单字符叠印。
- **保守判定要求重复性与视觉证据共同存在**；仅按字符内容、短行长度或某个中文字符的频率，不会删字。
- 确定候选后，按 Unicode 和相近 glyph 边界框将原始 RAWDICT 中的字符剔除，再重新拼接文本。为防止正文中同一个字刚好与水印覆盖，约束字形包围框尺寸比例和交叠面积。
- 如果预测删除占比超过 `--max-remove-ratio`（默认 35%），**不进行删除并写入回退记录**。严格的科研审稿可以把阈值降到 10–15%。
- 审计不代替人工判断：水印可能是正文上的浅灰高亮、图中纵向标签、浅色背景纹理或图号；页面必须回看渲染图。

## 3. 渲染策略

| 用途 | 推荐策略 | 理由 |
|---|---|---|
| 判断结构/页型 | 不渲染整本；只 `info`/`sample` | 避免 PDF -> 图片的无谓内存/IO |
| 常规图文校核 | 指定页 144–200 DPI PNG | 对大多学术页面足够辨读 |
| 公式、EDS、微观图局部 | `--clip-rel` + 300–450 DPI | 保持局部精度，避免整页超大图片 |
| 超大页面 | `--tile 2` 或 `--tile 3` | N×N 小图逐张处理，单张像素预算受控 |
| 渲染异常 | `parity` MuPDF 对比 PDFium | 分辨渲染器兼容性问题与原始对象问题 |
| 扫描 OCR | 200–300 DPI，逐页，PSM 3 | 仅在文字层不足时执行 |

无 `--pages` 的渲染使用代表页抽样，最多 30 页（除非 `--force-many`）。输出清单保留原图区域、DPI、引擎；同一页裁切图和全文文本可按 PDF 物理页码关联。

**坐标：** `--clip` 使用 PDF 点（pt, 1/72 inch），坐标原点左上；`--clip-rel` 使用 (0–1) 相对坐标，方便智能体定位图表。对特殊旋转/裁剪框 PDF，应先整页低分辨率渲染校对坐标。

**复杂图像：** 两种渲染器像素差异可来源于颜色管理、字形抗锯齿、表单、透明度混合；差异数值不是 PDF 质量的客观评分。

## 4. OCR 分流和图像型水印

- `--ocr auto` 的触发：页面原生文本量不足（默认 <45 字符）且图像覆盖率高（默认 ≥65%）。这只是启发式规则。
- 如果 PDF 是 **扫描图像+质量差的隐藏 OCR 字符层**，自动分流可能误判为已存在可用文字：先看 sample 和渲染图，再用 `--ocr force` 指定页。
- `suppress-light` 是可选的灰度像素阈值处理，可能同时抹除浅色水印**和**浅灰正文/图线，因此只用于人工确认的浅水印 OCR 案例；不可把其输出当作独立数据源。
- 扫描图片上的不透明字样如果遮挡了原文，任何解析都不能凭空恢复已丢失的字形信息。

## 5. 尚未实现、值得后续继续投入的模块

- **PDF XObject/OCG/注释分层归因：** 区分低透明 Form XObject、独立图像水印、optional content groups，按 PDF 绘制命令和复用对象 xref 聚类。
- **区域级版面模型：** 标题、摘要、表格、公式、双栏和边注块的语义排序；多栏情况下现在 `sort=True` 不保证完全正确。
- **OCR 质量评价：** 字符置信度、词典率、图文比对和双引擎 OCR（如 Tesseract + PaddleOCR）选择；需要额外依赖和真实样本基准测试。
- **精细 mask 渲染：** 先定位矢量水印的字符区域，在生成给 OCR 的临时页面图像时仅遮挡其像素，不触碰原 PDF；因为可能遮住正文交叉点，必须提供 before/after 对照及人工批准。
- **公式/表格验证规则：** 结构化比对数字、单位、公式编号和页码，自动标记与原页渲染冲突的记录。

## 6. 风险底线

1. 不以 `Producer` 决定是否 OCR。
2. 不把短行或常见字符当作垃圾数据。
3. 任何清洗留审计证据、源文件 hash 与回退路径。
4. 核心表格、关键公式、图中数据以原始渲染为复核依据。
5. 原件不被本工具覆盖或永久修改。
